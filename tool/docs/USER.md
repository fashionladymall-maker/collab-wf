# USER.md —— 给你的说明

你不需要打开命令行，也不需要记任何命令。所有操作都在 WorkBuddy 的聊天窗口里，用平常的话说就行。

## 你只需要会说这六句话

| 你想做什么 | 在聊天窗口里说 |
|---|---|
| 同意一件需要你批准的事 | **批准 K7P**（K7P 换成它给你的决定码） |
| 让它停下 | **暂停** |
| 让它接着干 | **继续 G2M**（同样带上决定码） |
| 撤回刚才那一版 | **退回上一版** |
| 交给它一件新事 | **新任务：……**（直接描述你要什么） |
| 问进度 | **现在到哪了** |

其他的事都不需要你做。看进度、查健康、修小问题、换新对话，都是执行端自己的活。

## 决定码是什么

需要你拍板时，它会在聊天窗口里发一段这样的话：

```
【需要你决定 · btc-quant · 决定码 K7P】
事项：需要你批准才能继续
原因：……
你回复：「批准 K7P」；或回复：「暂停」
不处理会怎样：驱动器保持停住，不会自动继续
```

照着回复引号里的话就行。码的作用是确认你批准的正是这一件事：如果你只回“好的”，它会再问你一次是哪一件；如果事情在你回复之前变了，旧的码会失效，它会把新的情况再发给你。

它只在这几种时候问你：动钱、密钥、是否合规、是否上实盘；它自己连续失败、或遇到没见过的情况；以及开始一个新项目时，请你确认哪些操作可以让它自己做、什么算做完。

## 想看一眼现在的情况

说“现在到哪了”，它会用一两句话告诉你。也可以说“打开看板”，在旁边看那一页：最上面就是需要你决定的事和要回复的话；下面是流程走到了哪一步、最近做了什么、下一次自动检查是什么时候。执行端不在的时候，看板照样会显示这些。

## 换新对话时

对话太长时，它会自己准备好交接材料，然后只请你做一件事：在 claude.ai 开一个新对话，把它给你的两个文件拖进去，再把它给你的一段说明发出去。其余的接续工作它会做完。

## 同时跑几个项目时

每个项目有自己的 Claude 对话、自己的定时推进，彼此不串。给某个项目开执行端（WorkBuddy）窗口时，请把工作区开在这个项目自己的目录下：唤醒是按目录找窗口的，开在别处，这个项目的待办就送不到它（会退回每小时一次的兜底）。

## 它不会做的事

不会在你没说的情况下批准任何东西；不会动钱、碰密钥、上实盘；不会改自己的规则。它做过的每一件事、依据是什么、你当时说了什么原话，都记在看板的“决策日志”里，你随时能查。
